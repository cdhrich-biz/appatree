# 작업 요청: 설정 페이지 시니어 오클릭 방지 + 홈 화면 바로가기 (기획 단계)

## 프로젝트 컨텍스트
- 서비스: APPATREE(아빠트리) — 시니어용 음성 기반 오디오북 웹앱
- 스택: React 19 + TypeScript + Tailwind v4 + Wouter, tRPC v11, Supabase
- 관련 파일:
  - `client/src/pages/Settings.tsx` — 설정 화면 (진입 즉시 모든 기능 노출 중)
  - `client/src/components/AppShell.tsx` — 헤더 톱니바퀴 버튼(라인 49~55)으로 `/settings` 진입
- 중요: **이번 작업은 구현이 아니라 "기획(설계 문서/플로우/와이어프레임 수준)"까지만 진행한다.** 실제 코드 구현은 추후 고도화 단계에서 별도 진행.

## 요구사항 1: 설정 진입 시 시니어 오클릭 방지 단계(게이트) 설계

### 배경
시니어 사용자가 무심결에 설정 버튼을 잘못 눌러 기능을 변경하는 것을 막아야 함.
현재는 톱니바퀴를 누르면 곧바로 모든 설정 항목이 노출됨.

### 기획해야 할 단계별 플로우
1. **설정 버튼 위치 재검토**
   - 시니어가 의도치 않게 누르지 않을 위치/형태로 설정 진입 버튼 배치 (현재 헤더 좌측 톱니바퀴 검토)
2. **설정 진입 직후 1단계 화면(안전 게이트)**
   - 화면 **가장 위쪽**에 **큰 X 형태의 "돌아가기" 버튼**을 배치 → 잘못 들어온 경우 즉시 빠져나가게
   - 그 하단에 **기능 설정으로 넘어가기 위한 진입 절차**:
     - 텍스트 입력란 제공 (예: 특정 단어/숫자를 입력하도록)
     - 입력 후 **"설정하기" 버튼**을 눌러야만 실제 기능 설정 화면으로 진입
   - 즉, "텍스트 입력 + 설정하기 버튼" 2중 확인을 거쳐야 실제 설정 기능에 접근 가능
3. **2단계 화면(실제 기능 설정)**
   - 게이트 통과 후에야 기존 Settings.tsx의 기능(글씨 크기, 음량, 속도 등)이 노출

### 기획 산출물(기대)
- 화면 전환 플로우(1단계 게이트 → 2단계 기능 설정) 다이어그램/설명
- 입력 텍스트 정책 제안(무엇을 입력하게 할지: 고정 단어 vs 안내된 숫자 등) 및 장단점
- 시니어 접근성 관점(큰 글씨/큰 버튼/대비) 반영안
- 와이어프레임 수준 레이아웃 설명

## 요구사항 2: "바로가기 버튼 만들기" (홈 화면 아이콘 생성) 설계

### 배경
설정 화면 내에 "바로가기 버튼 만들기"를 두고, 누르면 어떤 모바일이든 **홈 화면에 서비스 메인페이지 링크 아이콘**이 생성되도록 한다. (브레이브 브라우저 바로가기 형태 언급)

### 기획해야 할 내용
- 모바일 OS별(Android/iOS) 홈 화면 바로가기 생성 방식 정리
  - PWA "홈 화면에 추가(Add to Home Screen)" / `manifest.json` 활용 방안
  - 브라우저별(브레이브/크롬/사파리) 동작 차이 및 제약
  - `beforeinstallprompt` 이벤트 활용 가능 여부와 한계
- 버튼 클릭 시 사용자 안내 플로우(자동 생성 가능 범위 vs 수동 안내가 필요한 범위)
- 생성될 아이콘/이름/링크(서비스 메인페이지) 명세
- 기술적 제약으로 완전 자동 생성이 불가능한 경우의 대체 UX 제안

### 기획 산출물(기대)
- OS/브라우저별 지원 매트릭스
- 권장 구현 방식(예: PWA manifest 기반)과 근거
- 버튼 동작 시 사용자 경험 흐름(스텝별 안내)
