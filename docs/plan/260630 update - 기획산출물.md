## 요구사항 1 — 설정 진입 시 시니어 오클릭 방지 게이트

### 1.1 설정 진입 버튼 위치 재검토

**문제:** 현재 헤더 좌측 상단 톱니바퀴는 "뒤로가기"가 없는 홈류 화면에서 상시 노출되어, 시니어가 무심결에 누르기 쉽다.

| 방안 | 설명 | 시니어 적합성 | 권장도 |
|------|------|---------------|--------|
| A. 현 위치 유지 + 게이트로만 방어 | 위치는 그대로, 진입 직후 게이트로 차단 | 버튼 자체 오클릭은 여전 | △ |
| **B. 하단 네비 "더보기/설정" 탭으로 이동** | 톱니바퀴를 헤더에서 빼고 하단 네비 우측에 명시적 "설정" 탭 배치 | 위치가 일관·예측 가능, 라벨 텍스트로 인지 | ◎ (권장) |
| C. 헤더 우측 이동 + 라벨 동반 | 아이콘 + "설정" 텍스트 함께 | 인지 향상되나 헤더 혼잡 | ○ |

> **권장:** B안 — 단, 현 하단 네비는 직전 작업으로 **홈·검색·즐겨찾기 3칸**이다. "설정"을 4번째 칸으로 추가하면 칸이 좁아지므로, **헤더 톱니바퀴는 유지하되 아이콘 크기를 줄이고 터치 영역을 헤더 모서리로 한정**하는 절충(A+C)도 현실적. 최종 위치는 게이트 도입 효과를 본 뒤 사용자 테스트로 결정 권장.
> 핵심은 "**버튼을 옮기는 것보다 게이트로 방어**"가 본 요구사항의 주효한 수단이라는 점.

### 1.2 화면 전환 플로우

```
[홈/일반 화면]
     │  헤더 설정(톱니바퀴) 탭
     ▼
┌─────────────────────────────┐
│ 1단계 · 안전 게이트          │
│  - 최상단 큰 [✕ 돌아가기]    │   ──(✕ 탭)──▶ 직전 화면으로 즉시 복귀
│  - 안내 숫자 표시            │
│  - 숫자 입력란(숫자 키패드)  │
│  - [설정하기] 버튼           │
└─────────────────────────────┘
     │  입력 일치 + [설정하기] 탭
     ▼ (불일치 시: 흔들림 + 재안내, 게이트 유지)
┌─────────────────────────────┐
│ 2단계 · 실제 기능 설정       │
│  (기존 Settings 본문)        │
│  글씨/음량/속도/자동재생...  │
└─────────────────────────────┘
```

- **상태 모델:** `gatePassed: boolean` (페이지 로컬 상태). `/settings` 진입 시 항상 `false`로 시작 → 게이트 렌더. 통과 시 `true` → 본문 렌더.
- **재진입 정책:** 화면을 벗어났다가 다시 들어오면 게이트를 **다시** 통과해야 함(세션 유지 안 함). 오클릭 방지가 목적이므로 매번 확인이 안전.
- **뒤로가기 일관성:** 2단계에서 헤더 뒤로가기 → 홈으로(게이트 다시 노출). 1단계 ✕ → 직전 화면.

### 1.3 입력 텍스트 정책 (핵심 설계 결정)

원본은 "특정 단어/숫자 입력 후 설정하기"를 요구. 시니어(시력 저하·인지 부담 최소화) 특성을 기준으로 비교한다.

| 정책 | 입력 예 | 장점 | 단점 |
|------|---------|------|------|
| ① 고정 단어 | "설정" 입력 | 일관됨 | 한글 IME 전환·오타 부담, 키보드 조작 난이도 高 |
| **② 화면에 표시된 안내 숫자 따라 입력** | 화면 "**1234**" → `1234` 입력 | 기억 불필요(보고 따라 씀), 숫자 키패드로 단순, 시력 저하 시 큰 숫자로 안내 가능 | 화면을 봐야 함(시각 의존) |
| ③ 매번 랜덤 숫자 | 매 진입 다른 4자리 | 보안성 ↑ | 시니어에겐 변동이 혼란, 오클릭 방지엔 과함 |
| ④ 간단한 산수 | "3 더하기 5는?" | 무심결 통과 차단 강함 | 인지 부담 큼, 비권장 |

> **권장: ② 화면에 표시된 안내 숫자를 따라 입력.**
> - 숫자는 **세션 내 고정값 또는 단순 고정 안내값**(예: `1234`)을 큰 글씨로 화면에 노출 → 시니어는 "기억"이 아니라 "따라 쓰기"만 하면 됨.
> - 무심결에 톱니바퀴를 눌러도, 숫자를 보고 입력하는 **의식적 행동**이 1회 개입하므로 오클릭이 실제 설정 변경으로 이어지지 않음.
> - 입력란은 `inputmode="numeric"` + `type="tel"` 류로 **숫자 키패드 자동 표출**(한글 IME 회피).
> - 보안 목적이 아니라 **"의도 확인(intent gate)"** 이므로 난수·복잡도는 불필요. 단순함이 곧 접근성.

### 1.4 시니어 접근성 반영안

- **✕ 돌아가기 버튼:** 화면 최상단 폭 전체에 가까운 큰 터치 영역, 최소 높이 72px 이상, 아이콘 + "돌아가기" 텍스트 병기, 고대비(녹색/흰색).
- **안내 숫자:** `--text-senior-title`(현 36~40px) 이상으로 크게, 숫자 사이 간격 확보.
- **입력란:** 큰 글씨, 높은 대비 테두리, 포커스 시 녹색 강조(기존 `focus-within:border-green-600` 패턴 재사용).
- **[설정하기] 버튼:** 기존 `btn-primary` 스타일, 최소 높이 72px, 입력 일치 전에는 비활성(`disabled` + 흐림) 처리해 오작동 방지.
- **음성 안내(TTS):** 진입 시 `usePreferences().speak(...)` 재사용 — 예: "설정을 변경하려면 화면의 숫자 1234를 입력하고 설정하기를 누르세요. 잘못 들어오셨다면 위쪽 돌아가기를 누르세요."
- **오류 피드백:** 숫자 불일치 시 입력란 살짝 흔들림(shake) + "숫자를 다시 확인해 주세요" 큰 텍스트 + TTS 재안내. 게이트는 유지.
- **색상 외 신호:** 비활성/활성, 오류 상태를 색만이 아니라 텍스트/아이콘으로도 표현(색각 고려).

## 요구사항 2 — "바로가기 버튼 만들기" (홈 화면 아이콘 생성)

### 2.1 결론 요약

- 웹앱은 **OS 차원의 "홈 화면에 추가"** 메커니즘에 의존한다. 버튼 한 번으로 100% 자동 생성은 **플랫폼 제약상 불가**(특히 iOS).
- **권장:** 이미 갖춰진 **PWA `manifest.json` 기반** + (Android/Chrome 계열) `beforeinstallprompt`를 활용한 **반자동 설치**, (iOS/그 외) **그림과 함께하는 단계별 수동 안내**.
- **선결 과제:** 현재 **Service Worker가 kill-switch 상태**라 Chrome 계열의 자동 설치 프롬프트가 안 뜰 수 있음 → 최소 SW 재도입 필요(§2.5).

### 2.2 OS / 브라우저 지원 매트릭스

| 플랫폼 · 브라우저 | `beforeinstallprompt`(앱 내 버튼으로 설치 유도) | 홈 화면 추가 방식 | 비고 |
|---|---|---|---|
| Android · Chrome | ✅ 지원 | 버튼 → 네이티브 설치 시트 | 설치 조건(manifest + SW) 충족 시 |
| Android · Brave | ⚠️ 부분 | 대체로 지원하나 프라이버시 설정/휴리스틱으로 억제 가능 | 자동 미발화 대비 수동 안내 필요 |
| Android · Samsung Internet | ✅ 대체로 지원 | 버튼 또는 메뉴 "페이지를 홈 화면에 추가" | |
| Android · Firefox | ⚠️ 제한 | 메뉴 통한 수동 추가 위주 | 프롬프트 이벤트 미보장 |
| iOS · Safari | ❌ 미지원 | **공유 → "홈 화면에 추가"** 수동만 | 앱 내 자동 프롬프트 불가(정책) |
| iOS · Chrome/Brave/기타 | ❌ 미지원 | iOS 17.4+ 일부 외 대체로 Safari로 안내 필요 | iOS는 WebKit 단일 엔진 |
| Desktop · Chrome/Edge | ✅ 지원 | 주소창 설치 아이콘/버튼 | 본 서비스는 모바일 우선 |

> 핵심: **Android(Chromium 계열)** 는 버튼으로 유도 가능, **iOS** 는 수동 안내 불가피.

### 2.3 현재 PWA 자산 점검

| 자산 | 상태 | 조치 |
|------|------|------|
| `manifest.json` (name/short_name/icons/display/start_url) | ✅ 양호 | 아이콘이 SVG data URI — 일부 환경에서 PNG 선호. 192/512 PNG 추가 검토 |
| `index.html` PWA·apple 메타 | ✅ 양호 (`apple-touch-icon`, `apple-mobile-web-app-title`=아빠트리 등) | iOS 수동 추가 시 아이콘/이름 이미 적용됨 |
| Service Worker | ❌ kill-switch (fetch 핸들러 없음, 등록 안 함) | **§2.5 선결 과제** |
| manifest `shortcuts` `/chat` | ⚠️ 깨진 링크(AI 채팅 제거됨) | **§2.6 정리 과제** |

### 2.4 버튼 동작 UX 흐름 (설정 화면 내 "바로가기 버튼 만들기")

**공통 진입:** 설정 2단계(또는 별도 안내 화면)에 "📲 홈 화면에 바로가기 만들기" 버튼.

```
[바로가기 만들기] 탭
        │
        ├─ (이미 설치/standalone 실행 중?) ─ 예 ─▶ "이미 홈 화면에 있어요" 안내 후 종료
        │
        ├─ Android·Chromium + 설치 프롬프트 보유 ─▶ deferredPrompt.prompt() 호출
        │         └─ 사용자가 "추가" 선택 ─▶ "홈 화면에 만들어졌어요 🎉"
        │         └─ 사용자가 취소        ─▶ 수동 안내(아래)로 폴백
        │
        ├─ iOS · Safari ─▶ 단계별 수동 안내 시트:
        │     1) 아래 [공유] 버튼을 누르세요 (아이콘 그림 표시)
        │     2) '홈 화면에 추가'를 누르세요
        │     3) 오른쪽 위 '추가'를 누르세요
        │
        └─ 그 외/프롬프트 미보유 ─▶ 브라우저 메뉴(⋮) → '홈 화면에 추가' 그림 안내
```

- `beforeinstallprompt` 이벤트는 **미리 캡처(preventDefault 후 보관)** 했다가 버튼 클릭 시 `prompt()` 호출하는 패턴이 표준.
- **현재 상태 표시:** `window.matchMedia('(display-mode: standalone)')` 또는 iOS `navigator.standalone`으로 이미 설치 실행 중인지 감지해 중복 안내 방지.
- 모든 분기에 **TTS 음성 안내** 동반(시니어). 수동 안내는 **실제 버튼 모양 그림(아이콘)** 을 크게 곁들여 "어떤 버튼을 누르는지" 시각적으로 명확히.

### 2.5 선결 과제 — Service Worker 최소 재도입

Chrome 계열에서 `beforeinstallprompt`가 안정적으로 발화하려면 manifest 외에 **fetch 핸들러를 가진 활성 Service Worker** 가 사실상 필요하다. 현재는 의도적으로 kill 상태(`sw.js` 주석: *"나중에 PWA 캐싱이 필요해지면 완전히 새 경로(/sw-v2.js 등)로 재도입 권장"*).

- **권장:** 과거 캐시 크래시 재발을 피하기 위해 **새 경로(`/sw-v2.js`)** 로, **캐싱은 하지 않고 빈 fetch 핸들러만** 둔 최소 SW를 등록해 "설치 가능" 조건만 충족. (오프라인 캐싱은 별도 의사결정.)
- 이는 요구사항 2의 **자동(반자동) 설치 경로를 살리기 위한 전제**이며, 본 결정은 별도 구현 단계에서 진행.
- iOS는 SW와 무관하게 수동 추가이므로 영향 없음.

### 2.6 정리 과제 — manifest `shortcuts` 정합성

- `manifest.json`의 `shortcuts` 중 **"AI 추천" → `/chat`** 은 직전 작업으로 **제거된 기능**이라 깨진 바로가기가 된다.
- 후속 구현 시: 해당 shortcut 제거, 필요하면 "음성 검색"/"내 서재"만 유지하거나 다른 핵심 동선으로 대체.
- (참고) `shortcuts`는 홈 화면 아이콘 **길게 누르기** 시 뜨는 빠른 동작 — 본 요구사항의 "바로가기 만들기"와는 별개지만 같은 manifest를 쓰므로 함께 정리 권장.

### 2.8 기술 제약으로 완전 자동화가 불가능한 경우의 대체 UX

- **iOS:** 자동 불가 → "공유 → 홈 화면에 추가" **3스텝 그림 안내 + TTS**. "잘 안 되시면 가족에게 보여주세요" 류의 안심 문구.
- **프롬프트 미발화(Brave/Firefox 등):** 브라우저 메뉴(⋮) 경로 **그림 안내**로 폴백.
- **공통:** 안내 시트 하단에 "**다음에 하기**" 큰 버튼 — 강요하지 않음. 한 번 닫아도 설정에서 다시 시도 가능.
